# Modern IE 对照分析：原版形态与当前 Metro 实现

> 分析日期：2026-11-18
> 范围：Windows 8/8.1 的 IE10/IE11 Metro（immersive）界面 vs `Metro/` 当前实现
> 性质：设计对标记录，不代表已排期；本轮先新增文档，并已落地设置页重做与 A4（待实测）
>
> 结论先行：当前实现是「IE11 形态 + 现代浏览器能力」的混合体。视觉差距集中在
> **chrome 底色、活动标签描边、底栏密度、地址栏圆形按钮与输入框、标签/收藏/建议三个底部面板**；
> 功能上则应保留双内核、会话恢复、Tab Sweep、快速切换、Hub、无障碍等改进，
> 不应为了像原版而回退。

### 1.3 IE10 与 IE11 的区别

IE10 与 IE11 的标签入口形态不同：IE10 更接近顶部缩略图/AppBar，IE11 改为**底部统一的标签条 + 地址栏**。
当前 `Metro/` 实现明确是 IE11 形态，因此本文以 IE11 为主要参照；若要做 IE10 形态，应作为独立模式，
不在本轮范围内。

## 2. 原版形态（IE11 为主）

| 元素 | 观察到的形态 | 备注 |
|---|---|---|
| 窗口 | 全屏沉浸，无标题栏；页面占满屏幕 | 没有桌面窗口的标题栏/边框 |
| 底部 chrome | 标签条 + 地址栏合在底部；默认隐藏，底缘上滑/右键/Win+Z 唤出 | 可用 Settings 固定常显 |
| 标签条 | 紧凑；深色标签；活动标签为**深色底 + 强调色描边**；每个标签右侧 X | 不是蓝色填充 |
| 标签条右端 | `>` 滚动箭头、`+` 新建、`…` 更多 | 三个圆形按钮靠右 |
| 地址栏 | 左侧圆形后退；中间带边框的 URL 框（含 favicon）；右侧圆形刷新/星标/扳手/前往 | 没有主页/全屏按钮 |
| 地址输入框 | 未聚焦为深色边框框；聚焦后变白底黑字，右侧出现清除 X | 对比强烈，是标志性状态 |
| Tabs 面板 | 地址栏上方的底部面板；标题 “Tabs”；右上 `+`/`…`；缩略图横向排列；活动项描边 | 面板不遮住地址栏 |
| Favorites 面板 | 底部面板；标题 “Favorites” + 文件夹下拉 + 面包屑；文件夹磁贴与收藏磁贴 | 星标按钮进入 |
| Suggestions 面板 | 底部面板；三列（常用/搜索/网页）；右上 “Turn off suggestions” | 聚焦/输入时出现 |
| 阅读视图 | 地址栏按钮；Ctrl+Shift+R；Esc 退出 | 仅对文章型页面出现按钮 |
| 设置面板 | 右侧 346px；含 “Always show address bar and tabs” | 与当前宽度一致 |
| 手势 | 底缘上滑显示 chrome；左右滑动前进/后退；捏合缩放 | 触控优先 |
| 新建标签页 | 常用站点磁贴、固定站点、自定义磁贴图片 | 深色、磁贴化 |
| 命令入口 | 主要靠 `…` 与扳手菜单；没有常驻的底部 AppBar | 与 Windows 8.1 AppBar 不是同一层概念 |

## 5. 可更靠近原版：按性价比排序

### 5.1 第一批：低风险视觉签名（建议先做）

这一批只动 Metro 的样式与局部布局，不改数据层、不改主窗口、不引入新面板，风险最低，
但能立刻把“像不像 IE11”拉回来。

#### A1. 黑色 chrome + 活动标签强调色描边

- **为什么**：这是 IE11 最容易被认出的视觉签名。当前 `#2D2D30` 偏灰，活动标签蓝色填充
  更像 Edge/Windows 10，而不是 IE11 的“深色标签 + 描边”。
- **改动**：
  - `Metro/MetroColorPalette.cs`：新增 `ChromeColor`（`#FF000000` 或 `#FF0A0A0A`）、
    `TabColor`（`#FF333333`）、`TabActiveBorder`（`#FF0078D7`）；保留 `PanelColor` 作为面板层级。
  - `Metro/MetroTabStripControl.xaml` / `.xaml.cs`：活动标签不再设 `Background=MetroBlue`，
    改为 `Background=TabColor` + `BorderBrush=TabActiveBorder` + `BorderThickness=2`；
    模板里的 `Bg` Border 需要补 `TemplateBinding BorderBrush/BorderThickness`；
    hover 仍用白色 10% 叠加。
  - `Metro/MetroPage.xaml`、`Metro/MetroAddressBarControl.xaml`、`Metro/MetroAppBarControl.xaml`、
    `Metro/MetroTabGridControl.xaml`：底色统一到新 chrome 色。
  - 设置面板保持白色系统面板，不参与 chrome 黑底（见 A4）。
- **验收**：活动标签读起来是“描边”，不是“蓝底”；白字对比度足够；hover/pressed 仍可见；
  主窗口皮肤不受影响。
- **风险**：低。注意不要把所有面板都压成纯黑导致层级消失，可用 `#0A0A0A`/`#1A1A1A` 边框分层。

#### A2. 紧凑底栏 + 右端 `+` / `…`

- **为什么**：原版一屏能放 6–8 个标签，当前 200–260px 宽标签只能放 4–5 个；
  原版新建/更多在右端，当前 `+` 在左端，视觉重心相反。
- **改动**：
  - `MetroTabStripControl.xaml`：标签条高度 40 → 32；标签按钮高度 34 → 28；
    `MinWidth` 200 → 120，`MaxWidth` 260 → 180。
  - `MetroTabStripControl.xaml`：把 `Host` 从“ScrollViewer 直接铺满”改为
    `Grid`（`*` + `Auto`）：左列 ScrollViewer，右列固定 `+` 与 `…`。
  - `MetroTabStripControl.xaml.cs`：`Refresh` 先建标签，再把 `+`/`…` 放到右列；
    `…` 打开 `MenuFlyout`（标签视图、关闭所有标签、新建窗口、设置）。
  - `MetroAddressBarControl.xaml`：高度 48 → 44；`MetroPage.xaml.cs` 的
    `_bottomBarFullHeight` 初始值 88 → 76。
- **验收**：1280 宽下至少 7 个标签可见；`+` 在右端；`…` 可打开菜单；活动标签自动滚入视野；
  800 宽下不重叠、不裁切。
- **风险**：低–中。32px 标签条对触控略小，但比原版 24–26px 更安全；若坚持触控优先，
  可改为 36px 并接受密度稍低。

#### A3. 地址栏圆形按钮 + 边框输入框 + 聚焦白底/清除 X/前往

- **为什么**：这是仅次于活动标签的第二视觉签名。当前扁平图标 + 蓝色下划线是 Windows 10 语言，
  不是 IE11 的“圆形按钮 + 边框输入框”。
- **改动**：
  - `MetroAddressBarControl.xaml`：新增 `MetroCircleButtonStyle`：40×40、`CornerRadius=20`、
    `BorderBrush=#66FFFFFF`、`BorderThickness=1`、`Background=Transparent`；
    hover `#1AFFFFFF`，pressed `#33FFFFFF`。
  - 布局调整为：`后退 | 前进（可选） | URL 框 | 刷新 | 星标 | 扳手 | 前往`。
    原版没有前进按钮（靠手势），但当前保留前进是合理的可用性改进；可在不可前进时禁用。
  - URL 框改为 `Border` + `TextBox`：未聚焦 `Background=#1F1F1F`、`BorderBrush=#66FFFFFF`、
    `CornerRadius=2`；聚焦时 `Background=White`、`Foreground=Black`、placeholder 变灰，
    右侧显示清除 X。
  - 新增“前往”圆形按钮，调用现有提交逻辑；Enter 行为不变。
  - 星标按钮调用现有 `AddCurrentToFavorites()`；扳手按钮打开现有“更多”菜单。
  - 主页/全屏从地址栏移入扳手打开的“更多”菜单（仍可访问），避免右侧挤 6 个按钮。
- **验收**：聚焦时输入框变白、文字变黑、清除 X 可用；失焦恢复深色；圆形按钮 hover/pressed 正常；
  Go 提交、星标添加、扳手菜单、主页/全屏仍可到达；键盘 Tab 顺序合理。
- **风险**：低–中。重点测试焦点切换、IME 输入、清除按钮与 Esc 的交互。

#### A4. 设置里加“始终显示地址栏和标签”（已实现，待实测）

- **状态**：设置页已按 IE 截图重做为白色系统面板；`MetroAlwaysShowChrome` 已接入，默认开。
- **为什么**：这是 IE11 官方 Settings 里的选项，当前只有“滚动自动隐藏”，用户无法固定底栏。
- **改动**：
  - `MetroSettingsPanelControl.xaml`：新增 ToggleSwitch“始终显示地址栏和标签”，
    说明文字“关闭后向下滚动会收起底栏，向上滚动恢复”。
  - `MetroSettingsPanelControl.xaml.cs`：新增 `AlwaysShowChromeChanged` 事件。
  - `MetroPage.xaml.cs`：读取/保存 `SettingsManager` 键（如 `MetroAlwaysShowChrome`）；
    `OnTabScrolled` 在该项为 true 时直接 `ShowBottomBar()` 并返回。
  - 默认值建议 `true`，保持当前可见行为，避免升级后底栏突然消失；若追求原版默认，
    可设为 `false`，但要在设置里明确提示。
- **验收**：开关持久化；开 = 滚动不隐藏；关 = 当前滚动自动隐藏；打开设置/命令栏/查找栏时始终显示；
  与全屏、标签视图不冲突。
- **风险**：低。

#### A5. 阅读视图快捷键与 Esc

- **为什么**：IE11 的阅读视图有地址栏按钮、Ctrl+Shift+R、Esc 退出；当前只在“更多”菜单里，
  且 Ctrl+Shift+R 仍走刷新分支。
- **改动**：
  - `MetroPage.xaml.cs` 的 `Page_KeyDown`：Ctrl+Shift+R 调用 `ToggleReaderMode()`；
    Ctrl+R（无 Shift）保持刷新；Esc 在查找栏/设置/命令栏/网格/全屏之前，先判断阅读模式并退出。
  - 保留“更多”菜单项，作为可发现入口。
- **验收**：Ctrl+Shift+R 进入/退出阅读模式；Esc 优先退出阅读模式；Ctrl+R 仍刷新；
  菜单项状态（阅读模式/退出阅读模式）同步。
- **风险**：低。注意不要影响主窗口快捷键。

**第一批建议顺序**：A1 → A3 → A2 → A5（A4 已实现，待实测）。先改色与地址栏，视觉收益最大；
再改密度；最后补快捷键。

### 5.2 第二批：行为与手势（中风险）

#### B1. 底缘上滑先唤出底栏，而不是直接开命令栏

- **为什么**：原版底缘上滑是“把标签和地址栏叫出来”；当前底栏默认常显，所以上滑直接开命令栏，
  语义变成了“开 AppBar”。如果 A4 允许自动隐藏，底缘手势应优先恢复底栏。
- **改动**：`MetroPage.xaml.cs` 的 `Root_PointerMoved`：若 `_bottomBarHidden`，先 `ShowBottomBar()`；
  否则再 `OpenCommandBar()`。若“始终显示”开启，底栏已可见，上滑直接开命令栏。
- **验收**：自动隐藏状态下，上滑第一次出底栏，第二次出命令栏；常显状态下上滑直接出命令栏；
  不与页面滚动冲突（仅底缘 24px 起手）。
- **风险**：中。WebView2 内容区可能吞掉指针事件，需在 EdgeHTML/WebView2 分别验证。

#### B2. 左右滑动前进/后退

- **为什么**：IE11 官方支持 “swipe for forward and back gestures”；当前完全没有。
- **改动**：在内容区增加水平手势跟踪（阈值建议 80px 水平、40px 垂直容差，起手离左右边缘 >24px）；
  右滑 = 后退，左滑 = 前进；调用现有 `GoBack`/`GoForward`。
- **验收**：触摸右滑后退、左滑前进；不与横向滚动/轮播冲突；鼠标拖拽不触发；双引擎都可用。
- **风险**：中–高。WebView2 可能优先消费手势，需实机触摸测试；若不可行，至少保留键盘/按钮路径。

#### B3. 阅读视图地址栏按钮

- **为什么**：原版按钮只在“文章型页面”出现；当前没有地址栏入口。
- **改动**：在 `MetroAddressBarControl` 增加阅读视图按钮；先做一个 `CanEnterReaderModeAsync`
  检测（复用 `ReaderService` 的提取逻辑，不实际注入），可用时才显示；不可用时点击给出轻提示。
- **验收**：文章页出现按钮；点击进入/退出；非文章页不显示或提示；与 Ctrl+Shift+R 状态同步。
- **风险**：中。检测逻辑要避免重复提取造成卡顿，可缓存当前 URL 的检测结果。

#### B4. 全屏沉浸：隐藏底栏，手势唤出

- **为什么**：原版全屏没有任何 chrome；当前全屏只隐藏顶部标题栏，底栏仍在（除非滚动隐藏）。
- **改动**：进入全屏时 `HideBottomBar()`；底缘上滑/右键恢复；退出全屏恢复用户设置
  （“始终显示”则保持可见）。
- **验收**：全屏初始无 chrome；上滑/右键出底栏；Esc 先收底栏再退全屏；与 A4 设置兼容。
- **风险**：中。不要影响网页自身的全屏视频/游戏；可在检测到 HTML 全屏时暂停该行为。

### 5.3 第三批：结构级面板（高成本，需决策）

#### C1. Tabs 底部面板

- **为什么**：原版是“地址栏上方的底部面板”，当前是全屏三列网格；两者信息架构不同。
  底部面板保留页面上下文，切换更快；全屏网格更适合几十个标签的管理。
- **建议**：**新增**底部 Tabs 面板作为默认“标签视图”，保留全屏网格作为“展开”视图。
  这样既靠近原版，又不丢掉当前网格的多标签管理优势。
- **形态**：面板高约 180–220px；标题 “Tabs”；右上 `+`/`…`；100×62 缩略图横向滚动；
  活动项强调色描边；缩略图下方 favicon + 标题 + X；地址栏仍留在底部。
- **实现**：新建 `MetroTabsPanelControl`（或重构 `MetroTabGridControl` 为双模式）；
  复用现有缩略图生成逻辑；用 `GridView`/`ListView` 的横向虚拟化，避免之前
  `ScrollViewer+WrapGrid` 的布局冻结问题。
- **验收**：打开/关闭动画；选中标签关闭面板并切换；关闭 X 可用；活动项自动滚入视野；
  20+ 标签不卡顿；地址栏始终可见。
- **风险**：高。需要用户先决定“替换网格”还是“双模式”。

#### C2. Favorites 底部面板

- **为什么**：原版星标打开收藏中心，支持文件夹、面包屑、磁贴；当前 Metro 只能“添加到收藏夹”，
  完整管理要回主窗口 Hub。
- **建议**：做轻量 Metro 收藏面板，复用 `FavoritesManager`；Hub 继续作为完整管理入口。
- **形态**：底部面板；标题 “Favorites” + 文件夹下拉 + 面包屑；文件夹磁贴（`#213756` 一类）；
  收藏磁贴；右上添加/固定等动作；地址栏仍可见。
- **验收**：打开/关闭；进入文件夹/返回；选择收藏导航；新增收藏默认根目录；同 URL 全局唯一；
  删除/移动不崩溃；键盘可达。
- **风险**：高。注意与 R4-8 Hub 管理修复后的数据路径保持一致。

#### C3. Suggestions 底部面板

- **为什么**：原版输入时出现三列建议；当前 Metro 没有，主窗口的 flyout 也不能直接用。
- **建议**：先把 `ToolbarControl` 的建议查询逻辑抽成共享服务，再做 Metro 底部面板；
  首版做两列（常用站点 + 搜索/网址建议），跳过 Windows Store 应用建议。
- **形态**：地址栏上方底部面板；常用磁贴 + 建议列表；右上“关闭建议”；聚焦输入框白底 + 清除 X；
  ↑↓ 选择、Enter 跳转、Esc 关闭。
- **验收**：输入即出建议；键盘导航；无闪烁；隐私设置生效；性能可接受。
- **风险**：高。涉及跨控件逻辑抽取与输入法兼容。

#### C4. 命令栏去重（可选）

- **为什么**：当前命令栏与地址栏重复提供刷新/全屏/设置；原版没有常驻 AppBar，命令在 `…`/扳手。
- **建议**：保留命令栏作为右键 AppBar，但只放“新建标签/标签视图/更多”等非重复命令；
  刷新/全屏/设置回到地址栏或 `…`。若担心可发现性，可保留但默认收起。
- **风险**：中。属于信息架构调整，建议在 A/B 之后再评估。

## 6. 应保留的改进（不要为了像原版而回退）

| 能力 | 当前实现 | 相对原版的改进 | 在 Metro 中如何露出 |
|---|---|---|---|
| 双内核 | WebView2 + EdgeHTML | 现代站点兼容 + 旧版渲染保真 | 主窗口设置；Metro 继承默认引擎 |
| 会话恢复/懒加载 | `SessionTabs` + 标题持久化 | 启动更快、恢复更稳 | 无 UI |
| Tab Sweep | 搁置分组与 `SessionTabs` 分离 | 原版没有的“先放一边”能力 | 主窗口；Metro 可后续加入 `…` |
| 快速切换 | Ctrl+Shift+A 搜索当前窗口标签 | 比 Ctrl+Tab 循环更高效 | 键盘为主 |
| 预览带/垂直标签 | 主窗口有 | 多标签管理更强 | 主窗口保留，Metro 可不放 |
| 收藏管理 | 无限层级、全局唯一、上移/下移、Hub | 比 IE11 的文件夹更可控 | 主窗口 Hub；Metro 轻量面板为建议项 |
| Hub 五分区 | 收藏/阅读列表/历史/下载/集锦 | 信息架构比 IE11 更完整 | 主窗口；Metro 暂不链 |
| EPUB/PDF 批注 | R4 阅读器 + 文档打开 | 原版没有 EPUB/批注 | 打开文档时自动 |
| 朗读 | `ReadAloudService` | 原版没有页面朗读 | “更多”菜单 |
| 集锦 | Collections | 原版没有 | “更多”菜单 |
| 多窗口/拖出标签 | 多窗口、槽位恢复 | 比 IE11 的 side-by-side 更灵活 | 标签右键/`…` |
| 无障碍 | AutomationProperties、键盘导航、1809 清单 | 比原版更系统化 | 新按钮必须补名称 |
| 主题 | 主窗口明/暗；Metro 固定深色 | 原版只有深色 | 保持 Metro 固定，避免破坏还原 |
| 窗口化/高 DPI | AppWindow、窗口化、DPI 适配 | 原版全屏 only | 窗口化保留 |
| NTP 磁贴定制 | 纯色/Bing/自定义图片 | 比 IE11 的固定磁贴更自由 | NTP 内设置 |
| IME 安全快捷键 | 避免单字母快捷键 | 中文输入更安全 | 保持 |
| InPrivate | 每窗口、不持久化 | 比原版更明确的隔离 | 设置面板 |
| 查找栏 | Metro 底部查找栏 | 与原版 Ctrl+F 对齐且更可见 | Ctrl+F |
| 崩溃日志/幂等关闭 | `crash.log`、`_shutdownDone` | 原版没有的工程韧性 | 无 UI |
| 安全更新 | WebView2 运行时更新 | 原版 IE11 已停止支持 | 无 UI |

**原则**：功能能力留在“更多/设置/Hub”，视觉 chrome 尽量回到 IE11。不要为了还原而删掉
会话恢复、Tab Sweep、快速切换、无障碍等已经验证过的改进。

## 7. 不建议照搬

| 原版做法 | 为什么不建议照搬 | 建议 |
|---|---|---|
| 100 标签硬上限 | 当前无硬上限且能懒恢复，硬加限制是退步 | 保留无上限，用 Tab Sweep 管理内存 |
| 默认定时隐藏 chrome | 鼠标/键盘用户会觉得“工具栏消失”很烦 | 做成“始终显示”选项，默认可见 |
| 24–26px 标签条（截图估算） | 触控目标过小，无障碍不友好 | 32px 折中，保留原版密度感 |
| 全屏 only | 窗口化/多窗口是当前优势 | 保留窗口化；全屏时再沉浸 |
| 无前进按钮 | 鼠标用户仍需要前进 | 保留前进，不可用时禁用 |
| 主页/全屏按钮消失 | 可发现性下降 | 移入扳手/`…` 菜单，不删除 |
| Windows Store 应用建议 | 生态已不存在 | 只做站点/搜索建议 |
| 自定义收藏磁贴图片 | 成本高、收益偏个性 | 后续可选，不阻塞第一批 |
| 云端标签同步 | 隐私与本地优先策略冲突 | 不做；保留本地会话恢复 |
| 逐像素复刻图标 | 维护成本高，MDL2 更一致 | 用 MDL2，保持圆形按钮语言 |
| 只靠 `…` 隐藏命令 | 新用户难发现 | 保留命令栏作为右键 AppBar |

## 10. 一句话结论

当前 Metro 已经具备 IE11 的“骨架”（底部标签 + 地址栏、命令栏、设置面板、标签网格），
但“皮肤”仍偏 Windows 10：灰底、蓝填充、扁平图标、宽标签、全屏网格。第一批只改
**黑底 + 描边活动标签 + 紧凑底栏 + 圆形地址栏 + 始终显示开关 + 阅读快捷键**，
就能以很低的风险把还原度明显拉高；Tabs/Favorites/Suggestions 三个底部面板是下一阶段的结构级工作，
应先由用户决定是否用它们替换或补充现有的全屏网格与 Hub。
