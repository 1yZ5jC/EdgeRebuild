## 1. 文档方法与可信度

这不是二手资料，而是实机取证：

- **UI Automation 枚举**：每个按钮的自动化 ID、可访问名称、屏幕坐标、精确尺寸；
- **PrintWindow 表面截图 + 像素扫描**：色值、面板宽度、卡片间距均为实测；
- **包内 XAML / 资源键取证**：`SweptTabItemControl.xbf`、68 条 Sweep 资源键、PDF 遥测事件名等；
- **音乐应用**：Appx 解包到源码级（184 个 `.js`、160 个 `.html`、29 个 `.css`），配色/字号/布局均为明文。

**局限**：

- 单机单版本（Edge 44 / build 20348）、1200×932、亮色主题；尺寸是逻辑像素，可直接当 DIP 用；
- 部分行为未复现：Sweep 的“…”菜单未弹出；Sweep 面板在 UIA 树里完全不可见（0 项）；
- 音乐应用是服务下线后的“半成品”，空状态/错误态反而最有信息量；
- 因此“资源表里有”不等于“今天该做”，需要按价值/成本二次筛选。

## 5. 重点方案

### 5.1 Tab Sweep / Tab Center（P1，标志性）

旧 Edge 最独特、我们完全缺失的一块。今天仍有实用价值：**手动把整组标签“收进抽屉”，释放 WebView2 内存，稍后整组还原**。它与现有“标签挂起”互补——挂起是自动省内存，Sweep 是手动清空标签栏。

**产品形态建议：不要照抄两个按钮 + 两个面板，合成一个“标签页中心”。**

- 标签栏最左放一个 32×32 入口；
- 面板上半部“当前标签页”，下半部“已搁置的标签页”；
- 避免 Tab Center、Sweep、垂直标签、Metro 网格四套“看所有标签”的 UI 互相打架；
- 如果坚持高保真，再拆成两个入口，但共用卡片模板与数据层。

**数据与生命周期**：

- 新建 `SweptTabGroup` / `SweptTab` 表，**不要塞进 `SessionTabs`**，否则重启会把已搁置标签当成普通会话恢复；
- 关闭标签时用 `TabManager.CloseTabAsync(..., addToClosed: false)`，避免和“重新打开关闭的标签”重复；
- 清除浏览数据要连带清掉已搁置标签（文档资源键 `DeleteHistory_RecoveryStoreAndSweptTabs`）；
- InPrivate 下不持久化，或只允许内存内使用；
- 多窗口：记录所属窗口/槽位，或明确“面板全局、还原到当前窗口”，二选一。

**UI 规格**：

- 面板宽度按窗口 55.6% 计算，clamp 到 320–667px；
- 卡片 142×120、间距 6px、一行最多 4 张（`ItemsWrapGrid` 自适应）；
- 底色用主题令牌，不要硬编码 `#E6E6E6`；
- 时间桶：刚搁置/今天/昨天/更早即可，不必复刻 12 个桶；
- 卡片内容：缩略图 + favicon + 单行截断标题；无缩略图用灰色骨架占位（文档中 PDF 卡片就是占位图）。

**缩略图**：

- 复用现有 `_previewCache` 与 `WebCaptureService.CapturePagePngAsync`；
- MVP 可只持久化 URL/标题/引擎/位置，缩略图仅当前会话内存保存；重启后显示骨架；
- 不要为每张卡片阻塞 UI，按需/顺序捕获，设置超时。

**还原**：

- 保存原位置、引擎、固定状态；按原顺序插回；
- 旧 Edge 会把占位的新建标签页留下，这是怪癖；我们可选择还原时关掉未使用的占位 NTP；
- 单张卡片右键“删除”；整组“还原标签页 / 删除这些标签页”；“全部加入收藏”可复用 `FavoritesManager`。

**无障碍（重要）**：

- 文档明确记录旧 Edge 的 Sweep 面板在 UIA 树里完全不可见——**反面教材**；
- 用 `ListView/GridView` 做卡片，补 `AutomationProperties.Name`、键盘导航、焦点管理；
- 不要用一堆裸 `Border` + `PointerPressed` 拼面板。

**MVP 范围**：搁置整组 / 整组还原 / 删除整组 / 空状态 / 时间桶 / 持久化 / 无障碍。
**后置**：重命名、共享整组、首次引导动画（可先用空状态承担教学）。

### 5.2 Hub 空状态（P0，最低成本）

现在 Hub 的 `ListView` 为空时就是一片空白。文档三段式是“插画 + 一句文案 + 一个行动链接”；音乐应用更直接：“大标题 + 一个整宽行动按钮”。共同点：**必须给用户一个明确的下一步**。

建议做一个可复用的 `EmptyStateControl`（线框图标 + 标题 + 一句说明 + 一个主行动），按分区填：

| 分区 | 标题 | 行动 |
|---|---|---|
| 收藏夹 | 还没有收藏 | 从另一个浏览器导入（复用 `ImportFavBtn`）/ 浏览网页时点击 ☆ |
| 稍后读 | 稍后读是空的 | 在网页上点击阅读列表按钮 |
| 历史 | 还没有历史记录 | 开始浏览（InPrivate 提示已存在，保留） |
| 下载 | 还没有下载 | 下载的文件会显示在这里 |
| 集锦 | 用集锦收集灵感 | 新建集锦（复用 `NewCollectionGroupBtn`） |

不需要大插画，一条 MDL2 线框图标即可；重点是**只给一个主行动**，不要放三个同等权重的按钮。主题令牌 + `AutomationProperties.Name`。

### 5.3 菜单快捷键标注 + 缩放标题（P0，低成本）

- `AppMenuManager` 所有项目前都没有快捷键提示；
- UWP 用 `MenuFlyoutItem.KeyboardAcceleratorTextOverride` 直接加；
- **只标注真实可用的快捷键**，从 `ShortcutManager` 取，避免“看起来像”的键；
- 缩放保留子菜单，但把标题改成“缩放 100%”，不要强行在 `MenuFlyout` 里塞滑杆；
- 可顺手按旧 Edge 的分组加分隔线，但不要增加不工作的命令。

### 5.4 PDF 阅读栏（P1/P2）

现有阅读栏已是 40px，视觉节奏正确；缺的是状态与分组：

- **适合页面 ↔ 适合宽度**两态循环按钮（`page-fit` ↔ `page-width`），成本最低、最典型；
- **页面视图**浮层：单页/双页 + 连续滚动（pdf.js `spreadMode` / `scrollMode`）；
- 工具栏按“位置类靠左、呈现类靠右”重新分组，减少拥挤；
- 全屏时工具栏锁定/自动隐藏；页码滑条可选；
- 朗读后置：已有 `ReadAloudService` 与 `AudioIndicator`，但 PDF 文本提取 + 宿主桥接是中等成本；
- 30 色 + 连续粗细不照搬：现有 8 色 + 1–10 级够用，最多扩到 12 色。

### 5.5 历史 favicon（P1，低成本）

- 现在 `HistoryItemTemplate` 只有标题/URL/时间，无图标；
- 第一步不依赖网络：用域名首字母 + 固定色块（同一域名同色），成本极低；
- 第二步可选：从 WebView2 捕获 favicon 并入库，需给 `HistoryItem` 加字段/迁移；
- 视觉目标是“favicon + 标题/域名双行 + 右侧时间戳”，不是必须拿到真实 favicon。

### 5.6 标签预览带（P2）

- 现有悬停预览已覆盖核心；预览带是“常驻展开”的补充；
- 复用同一张缩略图卡模板，避免两套实现；
- 打开时按需捕获，不要一次性对全部标签 `CapturePreviewAsync`；
- 窄窗口/标签多时横向滚动，不要压缩卡片。

### 5.7 Web Notes 紫色模式（P2）

- 紫色是“模式色”的手段，不是目的；价值在“明确告诉用户当前处于批注状态”；
- 第一步：捕获覆盖层/ PDF 批注工具栏加紫色强调（标题条、激活按钮），不改整窗；
- 第二步（可选）：进入批注模式时把活动标签与工具栏染成 `#80397B`，其余保持灰色；
- 不要为了复刻把整个窗口染紫，破坏现有主题体系。

### 5.8 音乐应用文档的额外价值

1. **状态矩阵当 QA 清单**：空状态、成功反馈、聚焦、选中、播放中、上下文命令、轻量命令、模态、溢出、沉浸。拿这张表审计我们自己的下载成功/失败、标签挂起、InPrivate、加载/错误页。
2. **空状态是“行动优先”**，不是装饰优先。
3. **窄窗降级**：并列控件降为下拉、次要按钮收进“…”溢出菜单；审计 Hub 顶部“搜索 + 导入/导出/管理”在窄窗下的表现。
4. **单一强调色 + 三级中性色**：Spartan 主题已接近；不必追 2 个色值差，Acrylic 是刻意的现代选择。
5. **选择模式底部应用栏**：Hub 已有顶部管理栏，已覆盖需求；底部栏仅对触摸场景有意义，非必需。
6. **动画**：UWP 自带过渡已够；自定义动画风险大于收益。

## 6. 明确不建议照搬

- **PDF 独立进程 / DRM / 10 个错误页**：我们是 pdf.js in WebView2，进程隔离只增加成本。
- **扩展体系 / DevTools 独立 UWP 包**：WebView2 DevTools 已够用，扩展宿主是另一个项目。
- **30 色 + 连续粗细滑杆**：现有 8 色 + 1–10 级够用，扩大调色板只增加界面负担。
- **整窗紫色 Web Notes**：先做局部强调，不要为复刻把整个窗口染紫。
- **UIA 不可见的面板**：反面教材；Tab Center 必须可键盘/读屏访问。
- **纯平 `#F2F2F2` + 零圆角/零阴影**：与当前 Acrylic/圆角体系冲突；真要做，做成“经典皮肤”而不是改默认。
- **MSN 资讯流 / 固定 202px 标签宽**：前者是历史包袱，后者我们的自适应标签宽更好。
- **把缩放控件内嵌进菜单**：UWP `MenuFlyout` 不适合塞任意控件；用子菜单标题显示比例即可。

## 8. 已决策（2026-11-14）

1. **Tab Sweep 形态**：采用产品化“已搁置”抽屉，只做已搁置面板，不做当前标签列表；主题自适应，宽度 `clamp(内容区宽×55.6%, 320, 667)`，保留 142×120 卡片、时间桶与整组还原。
2. **顺序**：R4-1 quick wins 之后落地 Tab Sweep MVP。
3. **固定标签**：Sweep 时排除固定标签（用户锚点）。
4. **占位 NTP**：当前窗口保留自己的标签，不额外创建占位页；最后一个标签不参与搁置。
5. **InPrivate**：禁止 Sweep（入口按钮隐藏 + 数据层防御）。
6. **多窗口**：Sweep 组全局共享、不按窗口/槽位隔离；还原到发起还原的当前窗口。
7. **入口图标**：使用旧版 Edge 标签栏“已搁置的标签页”的堆叠窗口字形（`BrowserMDL.ttf` U+ED50），不采用“搁置标签页”的方框+左箭头；字体随应用打包到 `Assets/Fonts/BrowserMDL.ttf`，避免依赖系统未安装的字体族。
